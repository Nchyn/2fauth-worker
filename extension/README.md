# 2FAuth Worker 验证码扩展

一个轻量的浏览器扩展（Chrome / Edge / Firefox 121+），在工具栏弹窗和网页 OTP 输入框旁查看、填入 TOTP 验证码。

两种连接模式：

- **设备令牌（推荐）**：在站点「安全设置 → 浏览器扩展授权」生成令牌后粘贴到扩展。直接向站点取码，**不需要打开站点标签页**，令牌 30 天内滑动续期（每次取码自动延长）。
- **站点会话（回退）**：不填令牌时复用你在站点上已登录的会话，需要站点保持登录。

共同点：

- 验证码由站点侧计算，扩展**只接收当前验证码**，不保存账户密钥
- 纯原生 JavaScript，无构建步骤、无第三方依赖

安全锁（1.4.0 新增）：

- **系统级身份验证**：浏览器重启后首次打开扩展要求 Windows Hello（PIN/人脸/指纹）/ macOS Touch ID 验证，通过后本会话内免验证；验证码在锁定状态下任何路径都不显示（弹窗、OTP 面板均拦截）
- 平台不支持（如 Firefox/macOS 无 Touch ID）时自动降级为不锁
- 弹窗锁视图内可一键关闭安全锁

## 功能

- 打开弹窗时读取当前标签页域名，自动展示匹配的账户（「当前站点」分组）
- 在网页的 OTP 输入框聚焦时，旁边显示 2FAuth 验证码面板，点击填入
- 不会自动填写；只有点击验证码才会填入输入框
- 没有自动匹配时，可点账户右侧图钉手动绑定到当前站点
- 「显示全部账户」兜底：没有匹配时也能从面板选择任意账户
- 账户列表：服务名、账户名、当前验证码、倒计时进度条
- 点击账户行复制验证码
- 搜索服务名 / 账户名
- 按站点「分类」筛选（含「未分类」）
- 手动刷新；令牌模式下验证码过期会自动重新取码
- 支持 6/7/8 位验证码，以及常见的分格 OTP 输入框
- 授权失效时按模式给出对应提示（重新授权 / 打开站点登录）
- 快捷键：`/` 聚焦搜索，`Esc` 清空搜索

## 工作原理

### 设备令牌模式

1. 在站点「安全设置 → 浏览器扩展授权」点「授权新设备」
2. 点「发送到扩展」：站点页面通过内容脚本把令牌交给扩展
   - **首次绑定**：扩展不直接生效，会弹出「确认站点授权」界面让你核对域名后点「确认使用」——这是防投毒设计，确认前扩展不会显示该站点的任何验证码
   - 同站重新授权则直接生效，无需再次确认
   - 也可以手动复制令牌，粘贴到弹窗的「设备令牌」框（自己动手填的不经过确认步骤）
3. 扩展调用 `GET /api/ext/codes`（`Authorization: Bearer fw_...`），站点在服务端计算 TOTP
4. 响应里只有验证码，没有 secret；每次成功取码都会把令牌有效期续到 30 天后

> 为什么需要确认？内容脚本注入在所有网页上，理论上任何页面都能伪造一条「发送到扩展」消息并自建假接口通过校验。首次绑定必须经你在扩展弹窗里亲眼核对域名，恶意页面就无法抢先把自己绑成你的验证码来源。

### 站点会话模式（回退）

1. 你在浏览器里正常登录 2fauth-worker（Cookie + CSRF）
2. 弹窗或后台在站点页面中注入一小段代码，调用站点现有的 `GET /api/vault`
3. 这段代码在页面内用 WebCrypto 计算 TOTP，只把 `验证码 / 下一个验证码 / 周期` 返回给扩展
4. 内容脚本在 OTP 输入框聚焦时向后台请求**当前站点**匹配的验证码，并显示面板

因此：

- 扩展不接触账户密钥，只缓存短时效的验证码
- 设备令牌可随时在站点设置页吊销，吊销后立即失效
- 站点会话模式下，退出站点登录后扩展立即失效

### 站点匹配规则

2FAuth 的账户没有 URL 字段，所以匹配按以下顺序：

1. **手动绑定（最优先）**：点账户右侧图钉，把账户绑定到当前域名（如 `github.com`，自动覆盖子域名）
2. **服务名与域名相似匹配**：`GitHub` ↔ `github.com`、`Google` ↔ `accounts.google.com`、`Steam` ↔ `store.steampowered.com`
3. **常见别名**：阿里云 ↔ `aliyun.com`、微软 ↔ `microsoft.com` 等
4. 没有匹配时，可在网页面板点「显示全部账户」临时选择

## 安装

### Chrome / Edge

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本目录（包含 `manifest.json` 的文件夹）
4. 将「2FAuth Worker 验证码」固定到工具栏

> 从旧版本升级时，请在扩展管理页点一下「重新加载」。因为新增了后台脚本和内容脚本，浏览器可能会提示新增权限。

### Firefox

1. 打开 `about:debugging#/runtime/this-firefox`
2. 点击「临时载入附加组件」
3. 选择本目录下的 `manifest.json`

需要 Firefox 121+。Firefox 的临时加载在重启后会失效；长期使用可自行打包签名。

## 使用

1. 点击扩展图标，填写站点地址（例如 `https://2fa-worker.example.workers.dev`，不要带 `/api/v1`）
2. 选一种模式：
   - **设备令牌**：点「去站点授权」→ 站点「安全设置 → 浏览器扩展授权」→「授权新设备」→「发送到扩展」；或复制令牌粘贴到弹窗的「设备令牌」框
   - **站点会话**：在浏览器里打开站点并登录，令牌框留空
3. 点击「连接」

之后：

- 打开弹窗会自动显示「当前站点」分组，顶部徽标显示当前是「设备令牌」还是「站点会话」
- 在任意网站聚焦 OTP 输入框时，输入框下方会出现 2FAuth 面板
- 点击验证码填入；点面板里的「显示全部账户」可查看所有账户
- 如果当前站点没有自动匹配，可在弹窗里点账户右侧的图钉手动绑定

如果提示「设备令牌已过期或被吊销」：

1. 点提示条上的「重新授权」
2. 站点会打开「安全设置 → 浏览器扩展授权」
3. 授权新设备后点「发送到扩展」，或复制粘贴到弹窗

如果提示「未登录站点或登录已过期」（站点会话模式）：

1. 点击「打开站点登录」
2. 在站点完成登录
3. 回到扩展点「连接」或「重试」

站点地址支持子路径，例如 `https://example.com/2fa`。

## 缓存与安全

- 站点地址、设备令牌、令牌有效期和手动绑定关系保存在 `chrome.storage.local`
- 验证码缓存保存在 `chrome.storage.session`（仅内存，浏览器关闭即清空）
- 账户元数据（服务名/账户名）另存在 `chrome.storage.local`，仅用于重启后先渲染骨架，不包含验证码或密钥
- 账户密钥不会离开站点；扩展只拿到当前验证码
- 扩展只向**你配置的站点**发起请求，不上传任何数据到第三方
- 令牌模式只调用 `GET /api/ext/codes`，会话模式只调用 `GET /api/vault`，都不会修改站点数据
- 网页面板只在 OTP 输入框聚焦时出现；**不会自动填写**，必须点击验证码
- 内容脚本不会读取输入框里的内容，也不会读取页面其它数据，只把当前域名交给后台匹配
- 令牌可在站点设置页随时吊销，吊销后扩展的读取会立即失败（401），不会再显示新验证码
- 在站点退出登录后（会话模式），扩展的读取同样会立即失败（401/403）

## 系统安全锁（Windows Hello / Touch ID）

1.4.0 起，检测到平台认证器时默认启用：

- **解锁时机**：每次浏览器会话一次。浏览器重启后首次打开扩展要求系统验证（Windows Hello 的 PIN/人脸/指纹，macOS 的 Touch ID/系统密码），通过后本次会话内免验证
- **拦截范围**：锁定状态下，工具栏弹窗不显示任何账户与验证码；网页 OTP 面板只显示「扩展已锁定」提示。后台在锁定时拒绝一切取码请求
- **实现原理**：WebAuthn 平台认证器（`navigator.credentials.get` + `userVerification: 'required'`），凭证绑定在扩展自身 origin 上，注册时保存公钥、解锁时做**真实签名校验**。不新增任何权限；扩展接触不到你的 PIN/密码本身，验证全程由操作系统完成
- **降级**：检测不到平台认证器（典型如 Firefox/macOS）时自动降级为不锁，功能照常可用
- **关闭**：解锁后弹窗锁视图里有「关闭安全锁」；或解锁后从扩展管理页清除数据

注意：**解包加载**的扩展 ID 由目录路径派生——移动 `extension/` 目录或换机器加载会使已注册凭证失效（解锁页会提示验证被取消或凭证失效）。此时点「重试」不生效的话，用锁视图的「关闭安全锁」清除旧凭证后重新注册即可。

### 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存站点地址、设备令牌、手动绑定关系和会话级验证码缓存 |
| `clipboardWrite` | 点击账户时复制验证码 |
| `scripting` | 在站点页面内读取账户并生成验证码（仅会话模式） |
| `tabs` | 查找/打开站点标签页，读取完成后关闭临时标签页（仅会话模式） |
| `content_scripts`（全站） | 检测 OTP 输入框、显示验证码面板、接收站点授权 |
| `http://*/*`、`https://*/*` | 访问任意自建站点；只用一个域名时可自行改窄 |

## 限制

- 设备令牌模式需要站点为 **HTTPS**（或 `localhost`）
- 站点会话模式需要浏览器中已登录站点；未登录时无法读取
- 仅支持 **TOTP**（不支持 HOTP / Steam 验证码）
- 依赖站点的 `/api/ext/codes`（设备令牌模式）或 `/api/vault`（会话模式）；旧版站点没有 `/api/ext/codes`
- 本地时钟偏差超过 1 个周期时验证码会不准，可先同步系统时间
- 网页面板目前只处理顶层页面；跨域 iframe 内的 OTP 输入框不会被检测
- 识别数字输入框时排除了 `type="number"`（会丢失前导 0）；这类输入框请从弹窗复制
- 不支持编辑账户、图标包、共享、收藏等高级功能

```

├── manifest.json     # MV3 清单（后台 + 内容脚本）

└── README.md
```

## 本地预览（可选）

弹窗在没有 `chrome.storage` / `chrome.tabs` 的环境下会回退到 `localStorage` 和直接 `fetch`。可以模拟当前站点域名：

```bash
cd extension
python3 -m http.server 8080
# 打开 http://127.0.0.1:8080/popup.html?site=github.com
```

再准备一个返回 `/api/ext/codes` 或 `/api/vault` 的服务即可预览列表（响应中带上 `code`、`next_code`、`generated_at` 字段）。

内容脚本面板可以用一个带 `autocomplete="one-time-code"` 输入框的页面测试，并在加载 `content.js` 前用假的 `chrome.runtime.sendMessage` 返回验证码。

## 常见问题

**提示「设备令牌已过期或被吊销」**
- 令牌闲置超过 30 天，或在站点被手动吊销
- 到站点「安全设置 → 浏览器扩展授权」重新授权即可

**提示「站点尚未启用扩展接口，请先更新站点」**
- 站点版本较旧，没有 `/api/ext/codes`。更新站点，或清空令牌改用站点会话模式

**提示「未登录站点或登录已过期」（会话模式）**
- 先在站点完成登录，再回到扩展点「连接」/「重试」
- 站点 Cookie 有效期 7 天，过期后重新登录；想避免这一步请改用设备令牌

**提示「无法访问站点」**
- 检查地址是否带协议（`https://`）、是否误填 `/api/v1`
- 证书是否有效；HTTP 站点可能被浏览器按混合内容拦截
- 站点是否开启了额外的访问限制（如 Cloudflare Access）

**OTP 输入框旁没有出现面板**
- 确认输入框是页面顶层（不是跨域 iframe）
- 输入框需要有 `autocomplete="one-time-code"`，或名称/占位符包含 `otp`、`验证码` 等关键词
- 部分站点使用 `type="number"`，扩展不会自动识别，请从弹窗复制

**匹配到了不相关的账户**
- 2FAuth 没有 URL 字段，只能按服务名与域名启发式匹配
- 在弹窗里点图钉手动绑定后，会以手动绑定为准并保留自动匹配结果

**站点页点「发送到扩展」没反应**
- 确认扩展已加载并在该站点启用；重新加载扩展后刷新页面再试
- 首次绑定需要打开扩展弹窗完成「确认站点授权」，这是防投毒设计，不是故障
- 也可以直接复制令牌，粘贴到弹窗的「设备令牌」框

**确认页显示了不是我的站点**
- 说明有页面试图把自己绑定为你的验证码来源，点「拒绝」即可
- 之后请只在真实的 2fauth-worker 站点里重新点「发送到扩展」

**连接时看到标签页闪一下**
- 只有站点会话模式会这样：没有已打开的站点标签页时，扩展会临时开一个后台标签页读取数据，完成后自动关闭
- 改用设备令牌模式即可完全避免
